# pair-wise-yy-63 跨产品设计令牌治理与主题发布平台

维护基础令牌、语义令牌和组件别名，支持品牌主题、明暗模式与平台变体继承覆盖。
本版本将原本"整份覆盖 localStorage"的保存方式改造成**可恢复的协作账**：修订链 +
每层值 + 乐观并发 + 发布快照。

## 协作账模型

- **修订号与父修订**：每次令牌编辑生成一条主线修订 `rN`（含 `parent`、操作号、作者、
  直接改动的 cell、副作用列表），账本在 `localStorage`（`yy63-ledger-v2`）全序存储，
  通过 `storage` 事件跨标签页同步。
- **每层值（Layer）**：编辑先进入本标签页层（`sessionStorage`），只有显式"提交本层编辑"
  才会尝试进入主线。
- **并发提交**：提交带 `expectedParent`，两个标签页同时保存时只有一条能进入主线；
  另一条收到冲突，**本层值完整保留**，页面列出 `base / yours / theirs` 三方值。
  逐项"采用我的 / 采用主线"后才能重放；**冲突解决前发布暂停**。
- **操作号幂等**：每个操作带 `opId`，已应用的操作重复提交/恢复不会产生第二条修订。
- **写入失败恢复**：提交失败的操作进入 **outbox 未完成提交台账**，"协作账与发布"页可
  按操作号恢复；恢复时若主线已分叉则走冲突流程；已应用则识别为 `alreadyApplied` 不重复执行。
  顶部"模拟写入故障"按钮可把失败率调到 85% 演示该流程（URL 参数 `?fail=0.85`）。

## 分层解析与重算

令牌分三层：**基础令牌 → 语义令牌 → 组件别名**，解析顺序为
显式品牌覆盖 → `{token.id}` 引用（沿链回溯）→ 字面量。

- 基础令牌更新后，未覆盖的语义令牌和组件别名沿反向引用链**自动重算**（按主题分别计算），
  重算范围在提交前有"提交影响预览"，提交后记入修订的副作用并在依赖图上高亮。
- **显式品牌覆盖保留但待复核**：覆盖会截断重算传播，覆盖值不变，复核状态转为 `pending`，
  需在"品牌覆盖待复核"面板逐项"确认保留 / 放弃覆盖"，未复核完不能发布。

## 发布快照

冲突未解决、覆盖待复核、循环依赖、无效引用、对比度不达标或有待评审变更时，发布按钮暂停
并列出全部门禁原因。发布时冻结每个 cell 的解析终值、覆盖、校验和到快照；之后继续编辑，
**已发布包仍可按原修订/校验和查看**（发布页"发布快照"列表，只读横幅提示）。

## 页面

- **令牌工作区**：令牌树（分层/草稿/冲突/覆盖标记）、原始值与品牌覆盖编辑、Monaco JSON、
  四主题解析值、重算范围预览、待复核面板、主线新动态。
- **依赖与校验**：三列依赖图（基础→语义→组件），高亮草稿/重算/待复核/冲突/环节点。
- **变更评审**：接受变更进入本层草稿，再走统一提交。
- **协作账与发布**：发布门禁、未完成提交台账（恢复/放弃）、主线修订账（修订号、父修订、
  操作号、直接改动、重算/复核副作用）、未发布差异、发布快照列表。

## 技术栈

Vue 3、TDesign、Pinia、Vue Router、Monaco Editor、Vite、TypeScript。
核心逻辑（无 UI 依赖）在 `src/ledger/`：`types.ts`（模型）、`engine.ts`（解析/重算/校验）、
`storage.ts`（修订提交、幂等、恢复、发布快照）、`seed.ts`（初始令牌与覆盖）。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62063`。验证并发：开两个标签页，都改同一个令牌的同一主题后依次提交，
第二个标签页会出现冲突面板，第一个标签页通过 storage 事件实时看到主线推进。

```bash
npm run build
```
